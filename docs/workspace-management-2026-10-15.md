# 多企业 Google Workspace 管理

## 实现

- 新增主页面“企业目录”，企业选择、连接编辑、员工创建和维护均在主窗口内完成。仅选文件使用系统对话框。
- 每企业保存服务账号 JSON、管理员邮箱与管理 API 网络线路。Google OAuth 令牌与 Directory 请求共用显式代理，复用已有链式代理；独立住宅会话使用企业专用固定标识，不借用浏览器会话。
- 使用 Google 官方 google-auth 完成服务账号委托；固定 Google HTTPS 端点，不使用密钥文件自带的任意令牌地址、不跟随重定向、不隐式使用系统代理。
- 检测连接核实 Customer ID 和已验证域名。配置改动要求重新检测，跨企业替换连接、同企业重复建连接与跨企业执行预览均被拒绝。
- 分页同步员工到目录与账号库。已有密码、分组、备注、浏览器绑定保留；新同步员工没有密码，界面明确展示。云端移除的员工标记目录缺失，保留本机数据并阻止自动登录。
- 批量创建支持规则生成和 CSV；批量维护包括资料修改、重置密码、暂停和恢复。每批最多 200 行，默认不强制首次改密。资料只提交明确勾选的字段，禁止暂停连接管理员。
- 十分钟预览绑定企业、操作、配置版本和代理线路，服务端一次性消费；确认前可返回修改原表单。后台逐行执行，跨页持续显示任务活动与进度，可取消剩余行。
- 只有 Google 确认成功后才保存创建或重置的密码。写入超时标记未知，不重放请求；云端成功而本机失败单独提示。任务开始与进度写入本机，程序中断后提示先同步核实，不自动续跑。
- 企业任务执行期间保护关联账号、预留邮箱与代理线路，避免与本机编辑或自动登录互相覆盖。账号列表增加所属企业筛选，并区分本机密码编辑与云端密码重置。

## 使用边界

Google Directory 由离线提供方模拟，客户端传输、身份隔离、分页、失败与取消有独立验证；未向真实 Google 提交测试凭据，也未创建真实员工。首次实际连接需要企业自己的服务账号和域范围委托，两项作用域见 README。实际开户仍受企业额度、许可证及组织策略限制。

初版没有云端用户删除，后续已补充（见末节）；批量浏览器创建、集中批量自动登录和自动处理首次改密仍未实现。已有 Google/Dola 浏览器会话不会因目录同步被退出。程序的账号密码仍按既定需求明文显示和保存，企业私钥不通过状态接口返回；本机数据不纳入 Git。

## 管理员 OAuth 增补

- 企业连接默认使用管理员 OAuth，服务账号方式保留为高级选项。导入桌面应用客户端 JSON，保存后自动在系统浏览器发起授权，不要求全网域授权。
- 使用固定 Google HTTPS 端点、随机本地回调端口、PKCE S256、一次性 state 和 nonce。ID Token 使用 Google 签名验证，并核对 audience、issuer、邮箱验证状态和配置的管理员邮箱，再读取 Directory 核实企业 Customer ID 与域名。
- 访问令牌与离线刷新令牌持久保存，使用官方 google-auth 自动刷新并落盘。系统浏览器使用自身网络；令牌兑换、签名公钥获取及 Directory API 统一使用所选企业代理，支持两层代理，不读取环境代理、不跟随凭据端点或 HTTP 重定向。
- 各企业授权会话独立，可并行授权不同企业，同企业禁止重复授权或同时写入。五分钟等待超时、主动取消、用户拒绝、身份错误、企业重复、磁盘保存失败均明确反馈；失败保留原授权，取消后的迟到回调不写入凭据。
- 切换页面时继续等待授权，全局状态显示活动；在企业目录内展示状态与取消按钮。提供复制授权链接作为系统浏览器启动失败时的恢复入口，不展示令牌或客户端密钥。
- 新增后台 OAuth 专项测试覆盖真实回环 HTTP、PKCE、身份检查、令牌落盘/刷新、企业隔离、取消竞态、超时和失败路径。真实 WPF/Chromium 企业界面检查从 24 项扩展至 35 项，全部使用隔离样例和离线 Google 提供方。真实企业授权仍需用户导入自己的客户端 JSON 并在 Google 页面同意权限。
- Google 外部应用处于测试状态时，管理员必须列入测试用户，刷新令牌通常七天失效；长期使用需处理 Google 发布、验证及企业组织策略。
