# 栖航工作台：Windows 正式发布方案（草案）

日期：2026-10-16。当前项目名 Cloak Workbench，暂拟发布名“栖航工作台 / Qihang Workbench”。本文件保留最初完整规划；根据后续要求，当前先实现内置运行库和内核的简单内部离线安装版，具体操作见 `release/README.md`。组件管理平台与跨电脑迁移仍属于后续规划。

**当前实际交付：** `Qihang-Setup-0.1.0-beta.2-win-x64.exe` 是内置 Python、.NET 运行库及完整 CloakBrowser 内核的离线安装包，内容对应下表原定的 `Offline` 方案。为了保持安装入口一致，仍沿用 `Setup` 文件名。下表为早期规划，不代表目前存在三个发布物；在线精简包、独立内核组件包均未实现。新版同时提供企业授权、代理及可选账号和环境设置的跨电脑配置备份与恢复。

## 1. 建议采用的方案

主程序自带运行库，浏览器内核作为独立的受管理组件。默认提供标准安装包；首次使用浏览器时，检测本机内核，允许从官方渠道下载或导入合法取得的完整内核目录。允许内部使用时制作含内核的离线包，面向第三方的分发必须先落实上游授权。

这里的 CloakBrowser 是基于 Chromium 的完整浏览器程序，不是 Chrome 扩展插件。普通浏览器扩展是另一类东西。新电脑不需要先安装 Chrome，也不需要安装 Python、.NET SDK 或运行命令；只需安装我们的程序并准备可用内核。保持现有 WPF + Python 架构，没有必要为了打包重写为 Electron。

| 发布物 | 内容与用途 |
| --- | --- |
| `Qihang-Setup-0.1.0-beta.1-win-x64.exe` | 标准安装包，包含主程序、.NET 运行库和已冻结的 Python 后台；首次按需准备内核 |
| `Qihang-Offline-0.1.0-beta.1-win-x64.exe` | 同一套程序加已验证内核；用于允许的组织内部部署，或取得相应对外分发授权后发布 |
| 内核组件包 | 独立版本目录及完整文件、校验与许可信息；与主程序分别维护，不默认提供公开镜像 |

第一阶段只做 Windows x64 安装版。免安装版后做，且必须明确数据保存位置；直接拷贝程序目录不等于可迁移登录状态。安装包负责安装程序，数据迁移另有明确入口。

## 2. 现状与需要消除的开发机依赖

本机实测：内核目录 `chromium-146.0.7680.177.5` 约 535.9 MiB；`.tools/dotnet` 约 714.2 MiB，是开发 SDK；`.venv` 约 31.9 MiB，但引用外部 `D:\jiang\python`，不能作为独立运行时复制；当前桌面 Release 目录仅约 0.7 MiB，尚未包含 .NET 运行库。上述均为展开目录大小，不是安装包压缩体积。

| 当前实现 | 正式版调整 |
| --- | --- |
| `start-workbench.bat` → `launch.py` | 唯一桌面入口 `Qihang.exe`，负责启动后台、等待就绪、启动窗口和退出清理 |
| `.venv/Scripts/python.exe worker/server.py` | PyInstaller `onedir` 冻结为 `Qihang.Worker.exe`，内含 Python 与项目依赖；不要求目标机安装 Python |
| WPF `net8.0-windows` | 使用 self-contained `win-x64` 发布，包含运行库；不携带整个 SDK |
| `video_page.js` 运行时读取 | 明确纳入 Worker 打包资源；同时收集 tzdata、requests/certifi 证书与 google-auth 所需资源 |
| 默认读取开发机 `~/.cloakbrowser/...` | 组件管理器解析已安装内核，通过 `--browser` 传给 Worker；提供旧内核目录导入 |
| 程序根目录写 `data/`、`.local/` | 将安装目录、用户数据、缓存与日志分离；支持无管理员权限写入 |
| `127.0.0.1:8766` 写死在多处 | Worker 绑定随机空闲回环端口，启动握手传给界面；本地诊断网址也统一使用实际端口 |
| 启动异常仅开发日志 | 中文启动诊断，提供重试、修复组件、打开日志目录，禁止重复拉起多个 Worker |
| 环境变量 `CLOAK_WORKBENCH_ROOT` 同时承担多个用途 | 分离资源根目录、数据根目录与日志根目录，避免升级覆盖用户资料 |

冻结依赖采用锁定版本与哈希，记录 Python、.NET、Worker、内核版本。`onedir` 文件由安装器统一压缩分发；先不做每次启动解压的大型单文件包。打包后重点验证动态导入、时区数据、HTTPS 证书和 JS 资源，不能仅以“EXE 能打开”判定完成。

当前 .NET 8 接近支持结束日期 2026-11-10。首个内部验收包可沿用现有版本；发布 1.0.0 前优先升级到受支持的 .NET 10 LTS 并回归 WPF 嵌入、输入法和进程管理。目标机仍无需自己安装 .NET。

## 3. 目录和启动结构

默认按当前 Windows 用户安装，不请求管理员权限；安装器建议使用 Inno Setup。开始菜单、桌面快捷方式和卸载入口指向同一个启动程序。

```text
%LOCALAPPDATA%/Programs/QihangWorkbench/    # 安装目录，可替换
  Qihang.exe                             # 正式入口及 WPF 界面
  worker/Qihang.Worker.exe                # 冻结后台及运行依赖
  branding.json
  licenses/                              # 第三方许可与通知

%LOCALAPPDATA%/QihangWorkbench/            # 用户目录，升级保留
  data/                                  # 账号、代理、企业连接、任务、浏览器资料
    profiles/<environment-id>/
    downloads/<environment-id>/
  engines/win-x64/chromium-146.0.7680.177.5/
  settings/                              # 内核选择、下载线路、用户首选项
  logs/
  runtime/                               # 本次会话信息，不进入备份或安装包
  cache/downloads/                        # 下载中的临时文件
  backups/                               # 数据结构升级前的备份
```

用户可在设置里迁移数据目录到其他磁盘：停止相关任务和浏览器、检查空间、复制与校验后切换；中断保留原目录。初期不允许多个电脑同时写同一个共享数据目录。

启动顺序：检查单实例 → 检查数据目录与版本 → 按需备份及迁移数据 → 启动 Worker → 验证健康与协议版本 → 展示主窗口 → 展示内核状态。单实例按 Windows 用户隔离，采用命名互斥或系统锁。Worker 监听 127.0.0.1 随机端口，使用每次生成的认证密钥；密钥通过受控进程通信传递，不写入命令行或日志。

缺少内核时，账号、代理、企业目录和设置仍可访问；打开环境、自动登录、视频生成等依赖浏览器的操作指向组件安装流程。关闭主程序先停止自身任务和浏览器，再释放 Worker，不按进程名结束用户自己的其他 Chrome。

## 4. 内核组件管理

“设置 → 浏览器内核”使用主页面布局。首次缺少内核时显示欢迎页中的内核卡片，提供“从官方渠道获取”“导入已有内核”“稍后配置”。界面向用户解释为“浏览器内核”，不称为必须安装的插件。

展示：组件名称、提供方、已安装版本、工作台推荐版本、展开占用空间、状态和来源。操作提供下载、暂停/取消、失败重试、导入、校验修复、打开目录和清理未使用版本；没有验证过的版本标为“待验证”，不自动设为推荐。

下载状态按真实阶段显示：连接 → 下载（有 Content-Length 才展示实际百分比、大小与速度）→ 验证 → 解压 → 启动检查 → 可用。未知总量显示不定进度。错误区分网络、代理认证、空间不足、校验失败、版本不兼容，不使用虚构进度。

具体规则：

1. 先锁定当前已验证的 Windows x64 `146.0.7680.177.5`，不请求上游 `latest` 自动升级。新主版本可能改变功能、授权要求和并发限制。
2. 下载源必须是经过确认的官方发布地址，发布清单绑定版本、平台、压缩包大小与可信哈希；有上游签名时按固定可信公钥校验。哈希不能只来自同一个未经验证的下载响应。尚未确认的 URL、哈希或授权不以示例值启用下载。
3. 下载至 `.partial`；只有服务端支持 Range 且 ETag/Last-Modified 一致才续传，否则重新下载。取消不影响现有可用内核。
4. 解压到暂存目录，拒绝绝对路径、越界路径及不安全链接；校验核心文件后原子切换为可用目录，失败清理暂存区。
5. 必须保留完整运行文件，尤其 `chrome.dll`、`.pak`、`locales`、`icudtl.dat`、V8 和图形库；不能只复制 `chrome.exe`。首次打包先保留官方完整发布目录，裁剪需专项验证。
6. 验证版本、架构、必要文件与实际指纹参数。当前 `fingerprint.py` 通过父目录名解析版本；正式版应结合安装清单与实际版本，避免随意改名造成误判。
7. 组件下载使用单独的“下载网络”设置，允许明确选择直连、系统代理或手动代理并测试；不依赖尚未启动的浏览器环境。网络不可用时允许导入官方取得的离线包或完整目录。失败不擅自切换直连。
8. 关闭相关浏览器后才能切换内核。已有环境记录使用的内核版本，升级需备份 Profile；Chromium 升级可能迁移资料，回退时不能直接把新版资料交给旧内核。
9. 组件清理只清理未被环境引用的内核，经确认后执行；不得连带删除浏览器资料、账号或下载文件。

## 5. 内核授权与发布边界

2026-10-16 查询上游官方 [Binary License](https://github.com/CloakHQ/CloakBrowser/blob/main/BINARY-LICENSE.md)，版本为 1.3 / July 2026。包装器代码的 MIT 许可与浏览器二进制许可不同。

- 许可明确允许本人或组织控制浏览器流程的内部使用及内部存储，包括内部制品仓库；版本对应的订阅条款仍适用。因此“自己的其他电脑”和“对外发布给客户”要区分。
- 二进制条款限制向第三方重新分发、重新打包、捆绑，以及让第三方控制浏览器功能；这类 OEM/SaaS 集成需要单独许可。
- 条款允许列出依赖，由用户从官方渠道下载；但也单独规定了向第三方提供浏览器配置、会话控制能力的集成限制。我们的工作台恰好提供这些能力，不能把“让用户点击下载”当成当然免除 OEM/SaaS 授权。
- 上游目前仍说明 v146 是旧的免费版本；后续版本的下载、许可和会话限制需另行核实，不假定现有多开能力能原样迁移。

因此默认规划独立组件管理，内部部署可按许可制作内部完整包；准备公开给第三方使用前，落实 OEM/SaaS 许可或评估其他具备适当分发许可的内核。常规 Chromium 可作为未来兼容模式，但不能承诺它具备当前内核的指纹参数能力。内核许可联系人为上游 `info@cloakbrowser.dev`，不是本软件的用户支持邮箱。

## 7. 更新、数据保留和换电脑

主程序版本与内核版本分开。首版采用“检查更新 → 打开经过确认的发布页 → 用户安装新版”，不先实现后台静默自更新。安装器覆盖程序文件、保持用户目录；数据结构迁移前备份并记录版本，旧程序不直接读取已升级的数据。

安装包按明确白名单取构建产物，不从开发目录整包复制。绝不携带本机 `data/`、浏览器 Profile、密码、代理、OAuth 令牌、服务账号私钥、`.local/session.json`、测试证书、日志、缓存、`.git`、虚拟环境和 SDK。卸载默认保留用户资料，完全清理作为单独明确确认的选项。

换电脑分为两件事：

- **使用新软件**：空白用户数据开箱运行，准备内核、配置自己的网络线路和账号即可。
- **迁移已有资料**：后续增加明确的导出/导入入口，默认迁移账号、代理、环境设置与绑定关系，保留既有明文密码模式。导出包包含敏感资料，不能夹进软件安装包；导入前预览冲突并备份，不静默覆盖。

浏览器登录态不能保证随目录复制跨电脑可用。Chromium Cookie 可能受 Windows 用户/机器加密保护，当前本地加密会话备份使用 Windows DPAPI，也不适合直接搬到另一台电脑。需要在原电脑显式导出可迁移会话，在新电脑单独恢复并验证；IP、设备变化仍可能要求重新登录。企业 OAuth 建议在新电脑重新授权，避免多电脑共用和刷新同一令牌。配置为 `127.0.0.1` 的代理仅指新电脑自身，新电脑也需有对应代理服务，不能照搬后假定可连。

## 8. 实施顺序与发布验收

1. **发布基础**：接入品牌与关于页，整理安装目录 / 用户目录配置，取消开发机绝对路径依赖，改造唯一启动入口和随机端口握手。
2. **可独立运行的构建**：锁定依赖，冻结 Worker、收集 JS / 时区 / HTTPS 资源，发布 WPF 自包含版本；制作有白名单、可复现的构建脚本与许可清单。
3. **内核管理**：先做检测与导入，再做有可信校验的官方下载、进度、网络选择、失败恢复与版本管理。没有可用内核时让管理功能正常启动。
4. **安装器**：安装 / 升级 / 卸载、快捷方式、图标和版本，内部标准包与允许范围内的内部完整包；分发前明确许可与签名状态。
5. **干净系统验收**：无 Python、无 .NET SDK、无 Chrome、无 CloakBrowser 的 Windows 虚拟机 / 实机，从安装到正常退出验证；测试通过再定为 1.0.0。

验收必须覆盖：中文和含空格路径、普通用户权限、内核缺失、断网与下载中断、代理认证和链式代理、校验失败、磁盘空间不足、旧端口被占用、重复启动、杀后台后的恢复；验证邮箱密码输入、中文输入法、Ctrl+V、窗口切换、上传下载、指纹检查和会话重启。账号 / 企业 / 视频功能分别用隔离夹具回归，真实生成需用户明确操作。

升级和卸载专项检查：升级保留资料和绑定，失败能恢复数据，内核回退使用兼容资料，卸载不误删用户信息，发布包中不含开发机任何真实账号、令牌和浏览器会话。版本及授权信息明确展示；未在干净电脑跑过不能宣称“拿到任何电脑就能用”。
