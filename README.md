# Cloak Workbench

Windows 原生多账号工作台。账号列表独立保存 Google 邮箱与明文密码，浏览器环境可绑定账号执行自动登录；每个环境使用独立的 CloakBrowser 进程和持久化数据。包含账号管理、企业目录、代理、浏览器会话，以及复用现有 Dola 环境的文字视频生成任务。

操作反馈：代理检测、环境批量任务与企业任务全部成功后，结果提示约 4 秒自动收起；失败、部分失败、取消和待处理提示保留，可手动关闭。运行中的进度不自动隐藏。账号保存、删除和绑定成功提示也会自动清除，列表中的检测结果及已保存资料继续保留。

## 启动

安装版：运行 `dist/Qihang-Setup-0.1.0-beta.2-win-x64.exe`，完成后从桌面启动“栖航工作台”。内部安装包已包含 Python / .NET 运行库和当前浏览器内核，无需在目标电脑安装开发环境。安装包不包含开发机的账号、代理、Cookie 或企业授权；用户资料保存在 `%LOCALAPPDATA%/QihangWorkbench`，卸载默认保留。构建方法见 `release/README.md`。

完成依赖安装与构建后，双击 `start-workbench.bat`。

以源码方式运行时，先安装 Python 3.10+，执行 `powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1`。脚本把 Python 虚拟环境和 .NET 8 SDK 保存在项目内。源码仓库不包含 CloakBrowser 内核；内部安装包使用合法取得的现有内核，不能作为公开重新分发内核的授权。

本仓库只包含源码、测试和文档。账号数据、代理配置、浏览器 Profile、会话密钥、日志、依赖和构建产物均不提交；测试 TLS 证书与私钥运行时生成，执行相关测试需要 OpenSSL（Git for Windows 已包含）。

默认内核路径为 `%USERPROFILE%\.cloakbrowser\chromium-146.0.7680.177.5\chrome.exe`。可通过环境变量 `CLOAK_WORKBENCH_BROWSER` 指定其他兼容版本的可执行文件；更换版本后需要重新验证指纹行为。

## 已实现

- 深色三栏工作台、账号卡片和多标签；统一按钮、下拉菜单、滚动条与原生标题栏主题。
- 新建浏览器环境并选择代理和登录账号，检测出口后自动匹配语言与时区；指纹设置按需展开。已有浏览器与账号密码库分别管理。
- 账号名称、邮箱 / 标识、分组与备注；搜索匹配这些字段，按全部、已打开和需要登录筛选。运行中修改账号信息不重启浏览器。
- 只读 Dola 登录观察：页面加载完成后，Dola 返回明确的已登录状态、账号资料与当前账号菜单一致时确认登录；也支持可见退出入口。可见登录入口优先判定需登录，识别地区不可用提示，其余显示待确认。不会依据进程、Cookie 或匿名聊天界面推断登录有效，也不会自动发送消息。只回传判断所需布尔值，不回传网站账号资料或令牌。
- 分区编辑代理、语言、IANA 时区、固定种子、CPU、内存、WebGL 和屏幕指纹。
- 每个账号单独的持久化 Profile 和浏览器进程，关闭后保留登录状态。
- 真实浏览器窗口嵌入、标签切换、窗口缩放、地址导航、前进、后退、刷新。
- 将浏览器恢复成独立窗口，再重新嵌入。
- 实测内容边界后裁剪原生标题栏和边框；管理所属网页弹窗、原生文件选择器与每环境下载。
- 显示当前内核支持范围，读取网页实际暴露值，与配置逐项对照。
- 创建东京和首尔两个本地测试环境，展示网页实际读取的 Canvas、WebGL、CPU、内存、语言和时区。
- 关闭程序时先关闭本项目浏览器，后台服务只管理自身启动的进程。
- 本地服务监听 `127.0.0.1:8766`，每次启动生成独立 Bearer 密钥；配置和日志不进入 Git。

## 跨电脑配置备份与恢复

左侧“备份与恢复”在主窗口内导出和导入 `.qhbackup` 配置包。默认包含全部企业连接、管理员 OAuth 客户端与离线刷新令牌、服务账号密钥，以及代理账号密码、上游代理和住宅会话策略。账号与已知密码可选，环境设置与绑定也可选；选择环境时自动包含账号依赖。浏览器 Cookie、登录会话、下载、历史任务与员工目录快照不包含在配置备份中；导入后重新检测企业并同步员工。

导出时设置至少 8 位备份密码，文件使用 scrypt 派生密钥和 AES-256-GCM 加密，不依赖当前 Windows 用户，可在其他电脑输入相同密码恢复。不要遗失密码。导入先解密、校验和预览，默认跳过已有配置，也可明确选择替换。企业按 Google Customer ID 或管理员邮箱匹配，账号按邮箱匹配，并映射代理、企业、账号与环境的关联；代理和环境保留稳定标识。已有浏览器绑定冲突时停止恢复，不错误关联旧 Cookie。

确认导入前关闭浏览器并结束任务。程序会在用户数据目录 `data/config-backups/` 自动生成导入前的加密备份，使用本次输入的密码；写入失败回滚，多文件写入被中断时在下次启动加载资料前自动恢复原配置。预览十分钟有效，本机配置或导入策略改变后必须重新预览。成功提示约四秒自动消失，恢复摘要保留在页面。

有效 OAuth 刷新令牌通常可跨电脑使用，无须重新在 Google 同意授权；若 Google 已撤销授权、外部应用仍处于测试模式导致令牌过期，或组织策略要求重新验证，仍需重新授权。备份不延长授权有效期。`127.0.0.1` 上游代理指向新电脑自身，导入后需保证新电脑有对应代理服务。此功能迁移管理配置，不保证网站登录态跨电脑有效，也不变更云端员工。

## 账号列表与浏览器绑定

### 企业目录与批量员工管理

左侧“企业目录”在主窗口内管理多个 Google Workspace，默认使用管理员 OAuth；服务账号 JSON 保留为高级方式。每企业填写管理员邮箱并选择管理 API 网络代理，该代理与浏览器环境代理分别配置，支持已有两层链式线路。令牌申请、身份签名校验与 Directory API 共用所选线路，不自动回退直连；没有配置代理时明确使用本机直连。Google 授权页面在系统浏览器打开，使用该浏览器自己的网络线路。

推荐接入：在 Google Cloud 启用 Admin SDK API，配置外部 OAuth 应用及下方两项权限，创建“桌面应用”OAuth 客户端并下载 JSON。在测试模式下，将各企业的管理员邮箱加入测试用户。软件内添加企业 → 管理员 OAuth → 导入客户端 JSON → 选择 API 线路 → 保存，自动打开 Google 官方授权页面。选择对应企业管理员并同意权限，回到工作台等待身份与企业域名核实成功，随后点击“同步员工”。多个企业可使用同一个桌面客户端 JSON，但必须分别登录各自管理员授权；令牌和企业数据独立保存，不需要配置全网域授权。

软件使用随机 IPv4 回环端口、一次性 state、PKCE S256 和签名 ID Token（openid/email）核对管理员身份。授权可取消、五分钟超时，切页继续等待；系统浏览器无法打开时可以复制授权链接，在同一台电脑的可联网浏览器打开。重新授权失败或取消保留旧授权；更换管理员或 OAuth 客户端会清除该连接旧令牌。离线刷新令牌保存在本机并自动刷新，失效后提示重新授权；Google 外部应用测试模式通常在七天后需要重连，正式使用需根据 Google 要求处理发布、验证与组织策略。

若 Google 网页授权成功后回调失败，请查看回调页中文原因或工作台授权结果。浏览器能访问 Google 不代表程序本机直连可用：程序不会自动使用 Windows/浏览器系统代理，需要在代理列表添加可用外网线路（例如本机 HTTP 代理），再在企业连接设置中明确选择它。令牌兑换超时、代理连接失败、签名公钥获取失败、OAuth 客户端错误及已消费授权码有独立提示；不要刷新旧回调 URL，应修正配置后重新发起授权。最近授权结果只保存状态和安全说明，不保存回调 code/state 或令牌到状态响应。

高级接入：创建服务账号并下载 JSON 私钥；在该企业的 `admin.google.com` → 安全性 → API 控制 → 全网域授权中添加服务账号客户端 ID，授权下面两项作用域。软件内切换“服务账号 JSON（高级）”后导入密钥。客户端 ID 和作用域会在保存后的连接设置中显示，可选择复制。

```text
https://www.googleapis.com/auth/admin.directory.user,https://www.googleapis.com/auth/admin.directory.domain.readonly
```

OAuth 授权成功会自动读取管理员的 Google Customer ID 与已验证域名，服务账号方式需点击“检测企业连接”。一个企业连接绑定一个 Customer ID，不能把原连接改成另一企业，也不能把同一 Customer ID 重复添加为不同企业。服务账号密钥本身不等于企业权限，全网域授权和相应管理员权限仍需企业配置；创建用户受企业账号额度、许可证与组织策略限制。

“同步员工”读取完整分页目录，获取姓名、邮箱、启停状态、组织单位与部门，并同步到本机账号列表；已有密码、分组、备注和浏览器绑定保留。Google 不返回已有密码，企业员工列表的密码列在本机未知时留空；经系统创建或重置成功后，直接显示本机保存的明文密码，后续同步和重启继续保留，无须跳转到账号列表查看。在外部删除的员工不会自动删除本机记录或浏览器，但会标记目录已移除并停止自动登录。企业账号列表支持按所属企业筛选，账号详情注明本机密码修改与 Google 真实密码重置的区别。

员工表格仅展示邮箱、密码、姓名和状态，隐藏组织单位和部门列以优先展示完整邮箱；邮箱列加宽并获得更多剩余空间，悬停可查看完整内容。组织单位和部门仍可通过资料编辑维护，搜索继续支持部门。

每行另设“操作”列，直接修改该员工资料、重置密码、暂停 / 恢复或删除；暂停与恢复根据员工状态切换。行内操作只处理当前行，不改变或借用其他员工的勾选。顶部维护入口明确标为批量操作，需勾选 1–200 人。单行操作沿用页内编辑、预览和确认，删除仍需输入企业名称；任务或连接不可用时禁用操作，管理员删除受到保护。勾选和邮箱列固定在左侧，窗口较小时可横向滚动访问其他列及行内操作。

“批量创建员工”的生成方式下拉提供“人名＋4位数字”（默认）、“前缀＋递增序号”和“CSV 导入”，只显示当前方式需要的字段。人名模式自动选英文名、姓和 0000–9999，生成如 `danielcarter2153@企业域名`，员工姓名同时设为 Daniel Carter；只需选择已验证域名、数量、初始密码和组织单位。自动避开当前企业目录、本机账号库、本批次和仍有效的创建预览中的邮箱；有上限的重试耗尽会提示重新预览，不返回重复邮箱。尚未同步的云端用户、别名等冲突仍由 Google 最终校验。预览显示邮箱与姓名，确认执行固定使用该预览名单，不再次随机；返回修改后再次预览会生成新名单。前缀序号和 CSV 原有规则保留，CSV 内容不参与随机生成。

每批 1–200 人，先显示有效与错误行，核对目标企业后执行有效行。默认不要求首次改密，可明确勾选；开启时首次自动登录可能暂停等待改密，当前没有新增自动改密流程。CSV 使用以下表头；后三个资料字段可选，组织单位缺省为 `/`：

```csv
email,firstName,lastName,password,orgUnitPath,department,title,recoveryEmail
employee001@example.com,Employee,One,ExamplePassword123!,/,Engineering,Engineer,recovery@example.com
```

勾选目录员工后，可批量修改姓名、部门、职位、辅助邮箱或组织单位，重置密码，暂停、恢复和删除员工；只修改明确勾选的资料字段。连接管理员不能被本页面暂停或恢复。删除先预览，再勾选确认并准确输入企业名称；连接管理员、超级管理员和委派管理员禁止删除，执行前再次读取云端身份与权限。删除会移除 Google 云端员工，须先自行完成邮件、文件等数据交接；本机账号、已知密码和浏览器保留，标记目录已移除并停止自动登录。Google 确认创建或重置成功后，才将相应密码保存到本机账号库；随后可在账号列表为该账号创建环境、绑定浏览器并执行现有 Google 登录 Dola 流程。当前没有新增批量创建浏览器或批量登录调度。

Google Workspace 试用通常最多 10 人，Business Starter / Standard / Plus 最多 300 人；实际可创建人数还取决于订阅、许可证和组织限制，目录当前人数不能代表剩余额度。删除用户可使许可证供其他员工使用，但年度或固定期限订阅的账单不一定随之减少。参考 [Google Workspace 常见问题](https://workspace.google.com/intl/en_sg/faq/) 和 [删除用户说明](https://support.google.com/a/answer/33314)。

企业目录加载、预览、保存连接、OAuth 等待与后台任务使用页内遮罩卡片展示阶段；已知总量的任务显示实际进度、成功和失败数量，未知总量时显示流动进度，支持取消任务或授权。完成结果显示在列表上方，切页继续执行；每企业最多一个任务，全局最多四个。已发送的操作不会因取消撤回。写入超时或异常响应标记结果未知，不自动重放；若 Google 成功但本机写入失败，结果明确提示先同步核实并补录密码，不能重复创建。预览十分钟有效，只可执行一次；企业配置或代理线路改变后旧预览失效。程序退出会取消剩余行，重启后的未完成任务提示先同步核实，不自动继续执行。

连接密钥、OAuth 客户端与离线令牌、企业目录与最近结果保存在本机 `data/workspaces.json`，登录密码沿用 `data/login-accounts.json`；这些文件不进入 Git。状态响应不返回私钥、客户端密钥、访问/刷新令牌或任务中的密码；账号列表及企业员工列表的管理接口按明文显示需求返回对应账号的本机密码，企业员工列表同时核对企业、Google 用户 ID 和邮箱，不在目录快照中重复保存密码。

新增本机认证接口：`GET/POST /workspaces`、`GET /workspaces/<id>/users`、`POST /workspaces/<id>/check`、`POST /workspaces/<id>/sync`、`POST /workspaces/<id>/preview`、`POST /workspaces/<id>/execute`、`GET /workspace-jobs/<id>`、`POST /workspace-jobs/<id>/cancel`。OAuth 使用 `POST /workspaces/<id>/oauth-start`、`GET /workspace-oauth/<attempt>`、`POST /workspace-oauth/<attempt>/cancel`。执行接口只接受预览标识，实际员工和操作绑定在服务端；网页 Origin 请求继续被拒绝。OAuth 回调使用独立临时回环监听器，并验证 state，不复用管理 API 端口。

专项验证：`python -m unittest discover -s worker -p 'test_workspace*.py'`；构建界面测试程序后运行 `python tests/workspace_ui_probe.py --out .local/workspace-qa`。Google OAuth 和 Directory 使用隔离提供方，回环 HTTP、WPF 和 Chromium 使用真实实现；不向 Google 提交测试凭据、不创建真实企业员工。实际授权需导入自己的桌面客户端 JSON 后操作，或使用已完成委托的服务账号验证。

左侧“账号列表”只管理 Google 账号的名称、邮箱、密码、分组和备注，添加账号不会创建或打开浏览器。新增、编辑、绑定与删除确认均在主页面侧栏完成。密码以明文保存在 `data/login-accounts.json`，账号列表密码列直接显示明文，可选择复制；新增和编辑使用普通文本框，编辑时回填已保存密码。编辑时密码留空保留原密码，新增或更换邮箱需要填写密码。经过本机认证的账号列表接口返回密码供管理界面显示，浏览器状态摘要及日志不包含密码。此版本支持 Google 登录 Dola，其他平台暂未实现。

原“账号管理”更名为“浏览器”，原“批量管理 / 账号中心”更名为“环境管理”。环境名称、代理、指纹、Profile 和原有资料继续保留。创建环境或编辑环境配置可选择未绑定账号；浏览器菜单、环境详情也提供页内“绑定登录账号”入口。默认一个账号只能绑定一个环境，更换或解除绑定前须关闭相关浏览器，已绑定账号须先解除绑定才能修改邮箱或删除。

账号列表选中已绑定的账号后点击“使用绑定账号自动登录”，或在浏览器菜单执行同名操作，软件打开对应独立环境并在后台读取已保存密码，接入已有 Google 登录流程。验证码、两步验证继续手动处理，年龄声明继续逐次明确勾选。已有网站会话不自动退出或覆盖；自动流程若发现初始页面已经登录，会提示核对当前身份，绑定配置本身不证明网站当前登录的就是该邮箱。软件重启不会自动提交账号密码。

接受登录任务后直接显示对应浏览器，网页上方固定展示当前阶段、等待原因及继续、停止、检测登录入口；年龄声明也可在浏览器上方明确勾选。切换页面或运行环境保留各自任务状态，其他环境的进行中 / 待处理任务可从“其他任务”切换查看。Dola 首次加载登录入口可能需要几十秒；程序识别按钮及嵌套文字入口，不点击 Google Play 下载链接。导航造成的临时 CDP 断开或上下文切换会重新观察页面，已尝试的密码 / 授权操作不因回执丢失而重复提交；最终成功仍需 Dola 页面登录证据。

按环境记住的 Google 密码可通过“迁移已存密码”显式迁入账号列表并绑定；请先关闭对应浏览器。重复邮箱、已绑定环境和无效记录跳过，原凭据保留；没有记住密码的旧环境不会自动生成账号记录。迁移逐条执行，账号已保存但绑定失败时可在列表手动完成绑定。程序只读写明文密码；已有加密密码由本次升级的一次性转换处理。

本机认证 API：`GET/POST /login-accounts`、`POST /login-accounts/<id>/delete`、`POST /login-accounts/migrate`、`POST /profiles/<id>/login-account`（`accountId` 留空解除绑定）。`POST /profiles` 支持 `loginAccountId`，绑定与创建一同校验保存；公开环境状态中的 `loginAccount` 只包含账号资料与密码存在标记。登录继续沿用 `/profiles/<id>/google-login`；绑定环境使用 `useSaved=true` 时从账号库读取密码，邮箱必须匹配绑定记录。

专项验证：`python -m unittest discover -s worker -p test_login_accounts.py`；构建界面测试程序后运行 `python tests/proxy_ui_probe.py --login-accounts --out .local/login-accounts-qa`。界面回归使用实际 WPF、独立 Chromium 和本地 HTTP 服务，Google 提交阶段使用隔离状态机，不向真实 Google 发送测试密码。

## 批量环境与健康检查

左侧“环境管理”进入主窗口内的环境列表，“浏览器”返回浏览器工作区。可搜索环境、勾选多条、批量打开或关闭浏览器、修改分组和分配代理。浏览器启动逐个进入原生承载层；批量操作逐条显示结果，某条失败不会隐藏其他结果。运行中的环境可以改分组，重新分配代理必须先关闭浏览器。

环境列表分别显示浏览器环境和“关联 Google 账号”：环境下方显示分组，账号列显示实际绑定邮箱，未绑定时明确标注；完整邮箱可悬停查看，也能按邮箱搜索。关联账号表示自动登录使用的凭据，不代表已核验网站当前身份。环境与账号列固定在左侧，登录状态使用文字标签。任务执行期间显示进度和取消入口，完成后收起进度条，逐条结果可展开查看。详情按登录、网络、资料、用量分组，侧栏标题始终可见；小窗口保留筛选入口和表格横向滚动。

“批量创建 / 导入”先预览再确认创建，每次最多 200 条。支持按数量和前缀生成独立环境，也支持 CSV 或 JSON 账号资料；可设置统一分组和代理。重复邮箱（不区分大小写）、重复 ID 和无效行会逐条提示，合格行可继续创建。预览不修改账号库，提交时再次校验当前库中的重复项。

CSV 表头示例：

```csv
name,accountEmail,accountGroup,accountNotes
账号一,one@example.com,项目甲,主账号
账号二,two@example.com,项目甲,备用账号
```

JSON 示例：

```json
[
  {"name": "账号一", "accountEmail": "one@example.com", "accountGroup": "项目甲"},
  {"name": "账号二", "accountEmail": "two@example.com", "accountNotes": "备用账号"}
]
```

可选字段还有 `id`、`proxyId`。导入内容仅为账号资料，不导入密码、Cookie 或令牌；创建完成后仍需自行登录。每个新环境有独立指纹种子，账号资料导入不代表已登录。固定代理有可靠国家和时区快照时匹配地区；独立住宅会话或未知出口会提示先检测实际出口，并在环境配置中匹配语言和时区。批量导入不会自动发送公网检测，未匹配时保留默认语言 / 时区且使用手动地区模式。

账号详情展示账号资料、创建 / 最近启动时间、登录观察、实际代理检测及住宅会话。登录和网络批量检查最多并发 3 条，显示进度并可取消；已发出的连接在有限超时后结束，过时结果不会覆盖更改后的配置。登录检查只读已打开页面，不打开已关闭浏览器、不发送聊天；未知、需登录、地区受限和网络故障分别展示。检测快照保存在本机，历史结果应结合检测时间使用。尚未接入真实额度接口，详情中的额度显示未知。

本地 API：`POST /accounts/import`（`preview` 默认为 `true`）、`POST /accounts/batch`（`group` / `proxy`）、`POST /accounts/check`（`login` / `network`）、`GET /account-jobs/<id>`、`POST /account-jobs/<id>/cancel`、`GET /profiles/<id>/details`。

### 通过 Google 登录 Dola

在账号中心选中账号，进入“通过 Google 登录”；浏览器工作区的账号菜单也提供同名入口。邮箱和密码在页面内侧栏填写，点击“开始登录”后使用此环境原有的代理、指纹与持久化浏览器会话，自动寻找 Dola 的 Google 登录入口、填写邮箱和密码，等待返回 Dola。已有 Dola 登录会话会直接提示，无需重新提交密码。不会覆盖无关网页或清除 Cookie。

表单的“新账号步骤”默认启用 Google Workspace 欢迎页与 Dola 基础登录授权的自动处理；点击前复核官方来源和当前邮箱，只支持姓名、头像、邮箱的已知基础授权页面，额外权限或无法识别的页面仍暂停。年龄确认默认关闭，仅用户明确勾选“此账号使用者已满 18 岁”时自动确认 Dola 的 18 岁弹层，受理后清除勾选，不作为账号永久属性保存。支持截图中的中文与日文流程。

遇到验证码、两步验证、手机确认、账号选择、未授权的欢迎页 / 权限页或未确认的年龄提示时会暂停；点击“手动接管”，完成后返回表单点“继续登录流程”，无须重新输入密码，也可“检测 Dola 登录”。当前页仍需邮箱或密码时会提示重新开始，不在继续任务中保留或重放密码。每次填写任务只提交一次邮箱和一次密码；停止操作不会撤回已发送的请求。进度与操作固定在侧栏底部，小窗口的表单可滚动，年龄暂停时自动滚动到确认选项。

默认密码仅本次使用，任务受理后清空输入框，不写入账号资料、状态响应或日志。可自愿勾选“在本机记住密码”：将邮箱、明文密码和环境绑定后写入 `data/google-credentials.json`。已存密码只能在原环境与对应邮箱下复用，不会显示或回填到密码框。清除已存密码不会清除浏览器登录会话。软件重启后不会自动发起登录。

Google 登录接口沿用本机认证且拒绝网页 Origin：`POST /profiles/<id>/google-login`，`GET /profiles/<id>/google-login`，`POST /profiles/<id>/google-login/cancel`，`POST /profiles/<id>/google-login/continue`，`POST /profiles/<id>/google-login/verify`。开始和继续支持布尔字段 `allowOnboarding`、`ageConfirmed`，API 缺省均为 false；继续接口不接受邮箱 / 密码，只使用原任务绑定的环境和页面。凭据信息仅返回邮箱与是否已存，清除使用 `POST /profiles/<id>/google-credentials/forget`。

专项测试：`python -m unittest discover -s worker -p test_google_login.py`；`python tests/google_login_dom_probe.py --out .local/google-login-qa` 在真实 Chromium 中拦截所有网络并使用离线页面验证脚本；构建界面测试程序后运行 `python tests/proxy_ui_probe.py --google-login --out .local/google-login-qa`。这些测试不使用真实 Google 账号；真实网站的页面变化、网络、账号安全策略与实际登录仍需用户验证。

### 登录会话备份与 CK 导入

账号详情或账号菜单的“登录会话备份 / 恢复”进入页面内侧栏，分为本机备份与导入 / 恢复；账号中心右上角“导入 CK”可直接导入新账号。主要恢复按钮和进度固定显示，小窗口的表单可滚动，切换管理页保留预览与代理选择。

只读登录检测或 Google 登录确认成功后，后台自动更新本机加密快照，同一环境五分钟内不重复自动导出。也可点“备份当前登录”手动更新。备份只读取 Dola 域 Cookie 和当前 Dola 来源的 localStorage、sessionStorage、JSON 类型 IndexedDB；保留 Cookie 域、路径、HttpOnly、Secure、SameSite 和真实过期属性，保存指纹参数。普通浏览器 Profile 仍是日常持久化的主数据。

本机快照在 `data/session-backups/<环境ID>.json`，使用 Windows 当前用户 DPAPI 加密，文件不包含明文登录值。默认导出 `.ckbackup`，仅原 Windows 用户可解密；选择 CK JSON 可导出包含登录凭据的可迁移文件，请像密码一样保管。备份不导出 Google 密码或其他网站 Cookie，也不复制完整 Profile 目录。

支持 Cookie-Editor 常见 Cookie 数组、`cookies` / `cookies_list` 包装、dola-pool 状态文件以及含网站存储的完整会话包。先预览 Dola Cookie、过期数量与网站来源，再填写新账号名称并选择代理。导入总是创建新环境，完整备份保留指纹参数；普通 CK 使用新环境默认指纹。恢复先在离线来源页写入存储，再加载 Dola 并只读检测。导入成功、登录已确认、需要登录和地区受限分别显示；恢复失败保留新环境供手动处理，原账号不修改。

重新打开有备份的 Dola 环境时，只补回 Profile 缺失的会话 Cookie，并在身份 Cookie 一致时恢复当前来源的 sessionStorage。已有较新身份 Cookie 不被旧备份覆盖，环境指纹变化时跳过自动重放；localStorage 与 IndexedDB 继续使用 Profile 原数据。备份的服务器会话可能失效，改 IP 或改地区仍可能要求验证，不能通过修改本地过期时间延长服务器登录有效期。

当前 IndexedDB 快照仅支持 JSON 数据与 JSON 类型键。Date、Blob、二进制、循环引用等不支持的数据会使对应数据库跳过，备份摘要明确提示不完整；分区 Cookie 只支持 Dola 顶层来源。当前只自动采集所选 Dola 页面来源，其他来源仅保留同一登录身份下先前已采集的快照；这不是所有来源、所有类型的完整浏览器克隆。

本机认证 API：`GET/POST /profiles/<id>/session-backup`、`POST /profiles/<id>/session-backup/preview`、`POST /profiles/<id>/session-backup/export`（`format=encrypted/json`）、`POST /sessions/preview`（`text` 为文件内容）、`POST /sessions/import`（`draftId/name/proxyId`）。预览十分钟有效且只能确认一次；公开摘要不返回 Cookie 或存储值，仅显式导出接口返回文件内容。会话载荷上限 8 MiB，加密输入文件上限 16 MiB。

测试：`python -m unittest discover -s worker -p test_session_backup.py`；`python tests/session_backup_probe.py --out .local/session-backup-qa` 使用实际 Chromium 和离线 Dola 响应验证加密、恢复、关闭 / 重开以及拒绝虚假登录成功。构建 UI 测试程序后运行 `python tests/proxy_ui_probe.py --session-backup --out .local/session-backup-qa` 验证实际页内控件、代理选择与原生浏览器；真实网站会话有效性以用户账号检测为准。

### 住宅代理独立会话

代理编辑页支持固定凭据或“每个环境独立会话”。后者需要供应商确认支持的用户名模板，包含 `{user}` 和 `{session}`，例如供应商约定的 `{user}-session-{session}`；示例不是通用规则，应用不会擅自在原用户名后添加参数。上游代理和两层密码均保留。

会话标识按环境持久化，重启后保持。可配置有效时长（分钟，0 表示不主动过期）；到期后在浏览器已关闭且下次启动或实际检测时生成新会话，运行中的浏览器不自动更换出口。在账号详情中可手动轮换已关闭账号的会话，随后重新检测国家和出口。不同会话标识不保证获得不同 IP，供应商可能仍分配相同出口。

代理库的线路检测使用临时检测会话；账号检测使用该账号实际会话。线路检测国家不能代替每个账号的出口检测。会话索引保存在 `data/proxy-sessions.json`，账号检测快照保存在 `data/account-observations.json`，都不进入 Git。轮换 API 为 `POST /profiles/<id>/proxy-session/rotate`。

## 结构

```text
desktop/                .NET 8 WPF 界面和 Win32 HwndHost
worker/                 Python 浏览器生命周期与 CDP 控制
tests/                  原生窗口集成检查
data/profiles.json      账号配置（不提交）
data/profiles/<id>/      独立 Chromium Profile（不提交）
.local/                 运行日志和当前会话元数据（不提交）
launch.py               桌面和后台的启动及退出管理
```

第一版直接使用 WPF 画管理界面，减少验证阶段的组件数量。后续可以将管理界面换为 React/WebView2，继续保留原生浏览器承载层。

## 代理与下载

### 代理管理与环境选择

左侧“代理管理”在主窗口内切换到代理页面，集中保存普通代理和住宅代理；“环境工作台”返回浏览器页面。切页只隐藏和恢复原生浏览器，不关闭进程、不刷新网页，代理批量检测在切页期间继续运行。环境配置中的“管理代理 / 新建线路”在同一个编辑窗口内切换代理页，返回时保留未保存的环境字段。新建或编辑环境时选择代理库中的线路，也可选择本机直连；已有手动代理继续保留兼容选项，不会自动改变原来的网络。一个代理配置可以绑定多个环境。代理仍被环境引用时不能删除，绑定环境运行时不能编辑线路；关闭相关环境后修改，下次启动生效。

住宅代理必须填写**上游代理地址**，实际连接顺序为：本机 → 上游代理（外网通道）→ 住宅代理（最终出口）→ 网站。上游可填写已经运行的本机代理，例如 `http://127.0.0.1:7897`，其端口必须与实际外网代理一致。两层分别支持 HTTP、HTTPS、SOCKS5 和独立认证；住宅网关域名由上游解析，任何一层失败都不会回退直连。默认固定凭据模式原样保留供应商用户名；独立环境会话需要明确开启并填写供应商支持的用户名模板。

代理列表支持检测当前、勾选批量检测和检测全部，最多并发 3 条，展示进度并支持取消待处理项；已开始的连接在有限超时后结束。IPPure 优先提供一次响应中的出口 IP、耗时、国家、地区、ISP、ASN、住宅属性和风险信息。IPinfo 仅补全相同出口的数据，主服务失败时依次回退 IPinfo、IPify；所有请求经过同一代理链。轮换住宅代理可能每次连接选择不同出口，此时保留完整单次快照并单独标注出口变化，不清空全部字段或混用不同 IP 的风险、地区数据。住宅属性或风险数据缺失时质量分显示未知。

检测时列表上方显示状态卡、旋转图标、真实完成数和耗时；首条结果返回前显示流动进度，之后按实际结果平滑推进。每条代理显示等待或检测状态，旧结果淡化，完成后逐条更新并汇总成功、失败与跳过数量。轮询保留行实例和选择状态，切页后任务继续；编辑代理中的线路检测也提供加载状态。Windows 关闭界面动画时旋转与过渡停止。

代理地址可以直接粘贴 `username:password@host:port`、`host:port` 或带 `http://`、`https://`、`socks5://` 的完整地址。未写协议时采用 HTTP，即使端口为 443 也不推断为 HTTPS。认证 URL 保存时拆分地址、用户名和密码，用户名的地区、ASN 和会话参数完整保留。检测已有且未改变的编辑器线路时，结果同步到代理列表；仅更改名称再保存会保留检测结果，更改线路或认证后需要重新检测。

质量分是本地参考计算：延迟最高 25 分、明确住宅属性 35 分、风险最高 40 分（风险越低得分越高），不是网站可用性承诺。检测详情提供信息来源和时间。列表地址不含认证信息，两层密码只写不读；密码目前保存在本机 `data/proxies.json`，未启用 DPAPI 加密。

新增 API：`GET/POST /proxies`、`POST /proxies/<id>/delete`、`POST /proxies/test`、`POST /proxies/check`、`POST /proxies/<id>/check`、`GET /proxy-checks/<id>` 和 `POST /proxy-checks/<id>/cancel`。环境通过 `proxyId` 绑定线路；原 `/proxy/test` 和环境检测接口继续支持已有配置。

代理管理界面验收使用 `tests/proxy_ui_probe.py` 连接隔离后台，批量诊断数据明确为测试示例；不向用户代理库添加样例。`tests/proxy_chain_live_probe.py` 使用自有本地双认证中转检测固定公网服务，不读取商业代理凭据。真实 Chromium 的代理库绑定与两跳认证由 `worker/test_proxy_api_flow.py` 验证。

代理地址支持 `http://host:port`、`https://host:port` 和 `socks5://host:port`，用户名和密码分别填写。兼容旧式带凭据的代理 URL，保存时会拆分凭据。HTTP/HTTPS 使用 Basic 代理认证，SOCKS5 支持用户名密码认证和代理端域名解析。HTTPS 上游使用系统 CA 校验服务器证书和主机名。

每个运行环境使用独立的临时回环中转，浏览器命令行只包含中转地址；上游密码不会写入浏览器命令行、API 状态或错误消息。关闭环境、退出或启动失败时释放中转。密码目前以明文保存在本机 `data/profiles.json`，该目录由 Git 忽略；尚未使用 Windows DPAPI 加密。不要分享 `data/` 或 `.local/` 文件夹。

启用代理的环境同时设置 Chromium WebRTC 策略 `disable_non_proxied_udp`，限制绕开代理的直接 UDP 连接；直连环境不修改该策略。Chromium 对回环地址的默认代理绕过仍保留，供本地验证页使用。这不是完整的匿名性保证，公网 DNS、WebRTC、扩展及不同内核版本仍需结合实际网络测试。

测试代理请求固定 HTTPS IP 服务，显示出口 IP、耗时及成功或失败；直连会明确标为直连。不会接受任意测试网址，也不会因系统 `NO_PROXY` 配置绕过已选择的中转。公网服务不可用、认证失败或 TLS 错误都会返回失败，不把配置通过当作连接成功。

下载保存在 `data/downloads/<id>/`。后台持续保留设置下载行为的浏览器 CDP 会话，避免一次性连接断开后 Chromium 重置下载路径；下载列表区分完整文件与 `.crdownload` 临时文件。

以下本地 API 均要求当前会话 Bearer 密钥，并拒绝带 `Origin` 的网页请求：

| 路由 | 用途 |
| --- | --- |
| `POST /profiles` | 创建或编辑环境，密码只写不读；省略密码保留已有值，`clearProxyPassword: true` 清除密码 |
| `POST /proxy/test` | 测试尚未保存的代理设置；已有环境可传 `id` 和 `keepProxyPassword: true` 使用保留密码 |

| `GET /capabilities` | 查询当前安装内核可识别的指纹参数 |

| `GET /profiles/<id>/downloads` | 查询该环境自己的下载目录和文件 |

代理线级回归覆盖 HTTP Basic、CONNECT 双向转发、HTTPS 上游证书校验、SOCKS5 用户名密码和域名转发、错误响应、中转关闭及启动失败清理。真实浏览器通过带认证的本地 HTTP 代理读取保留测试域名；独立临时 API 流程验证了实际浏览器下载至环境目录、环境读数和公网直连出口查询。商业代理和不同认证方式仍需使用实际配置逐项验证。

## 边界

跨进程 `SetParent` 不是 Chromium 官方嵌入接口。本机验证结果不能替代不同 Windows、DPI、输入法和内核版本的兼容测试。弹窗和文件选择器保留独立原生窗口，可从工具栏查看、切换和请求关闭；普通 WPF 浮层不能直接覆盖原生承载区。

当前标题栏使用原生 UIA 内容边界裁剪，实测网页内容与承载区四边差值为 0 像素。无法测量的内核会保留原窗口，避免裁掉网页。截图仅针对本项目窗口；后台 `PrintWindow` 可能无法捕获 Chromium 网页像素。

当前内核为 Chromium 146.0.7680.177.5，参数按本机实际内核能力开放。初始窗口宽高与网页读取的屏幕指纹分别配置；选择 macOS 平台不会自动安装 macOS 字体或改变真实操作系统。配置值一致不等于通过所有网站的指纹检测。

新建与编辑环境的语言、时区、系统平台、逻辑处理器数、内存及屏幕分辨率采用下拉选项。地区方案联动填写语言与时区，例如日本使用 `ja-JP / Asia/Tokyo`，美国可选择东部、中部、山地或西部。时区还包含系统提供的 IANA 映射选项，已有配置中的自定义值会保留为选项。

“一键随机指纹”保留当前语言、时区、平台、代理和基本信息，更新固定种子、CPU / 内存组合、屏幕及任务栏高度，并将 WebGL 恢复为内核按种子生成。高级设置保留种子、噪声开关和自定义 WebGL；不支持的参数禁用且不随机修改。结果在保存后下次启动生效，普通保存或重新打开编辑器不会重新生成指纹。默认新环境已经有独立种子，其余硬件可保持自动。
